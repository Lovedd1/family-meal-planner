# 做饭记录页面设计文档

## 概述

做饭记录页面（Cook）用于记录用户每日做饭的情况，拍照归档，与点餐系统联动，形成完整的饮食闭环。

## 定位

方案二 B：标准归档版

## 功能规划

| 功能 | 描述 |
|------|------|
| **拍照记录** | 拍照/相册选择 → 关联菜品（搜索/下拉） → 保存 |
| **关联餐次** | 自动识别：08:00前=早餐，11:00-14:00=午餐，17:00后=晚餐（可手动改） |
| **评分系统** | 1-5星评级，点击星星选择 |
| **历史列表** | 按日期分组（今日/昨天/本周/更早），卡片式展示 |
| **详情页** | 大图 + 菜品信息 + 评分 + 备注 |
| **统计页** | 本月做菜数、最爱菜品TOP3、平均评分 |

## 页面布局

### TabBar 配置

底部两个 Tab：
1. **记录** - 默认选中，展示历史记录列表
2. **统计** - 本月统计报表

### 记录 Tab 布局

- 顶部：月份切换（`< 2026年5月 >`）
- 中部：历史记录卡片列表（按日期分组）
- 底部：粉色圆形拍照按钮（固定定位）

### 拍照流程弹窗

1. 拍照/选择图片
2. 关联菜品选择器（搜索 + 下拉列表，显示 emoji + 名称）
3. 餐次选择（早餐/午餐/晚餐，可改）
4. 星级评分（1-5颗星）
5. 备注输入（可选）
6. 保存

### 统计 Tab 布局

- 本月做菜数（大数字展示）
- 最爱菜品 TOP3（emoji + 名称 + 次数）
- 平均评分（星星展示）
- 历史趋势（可选）

## 数据模型

```js
// 本地存储 key: cookingRecords（数组）
{
  id: 'cr_xxxxx',           // UUID
  date: '2026-05-07',       // 日期
  meal: 'lunch',            // breakfast/lunch/dinner
  imagePath: '本地图片路径',  // 本地存储路径（wx.env.USER_DATA_PATH）
  menuItemId: 'menu_xxx',   // 关联菜品ID
  menuItemName: '土豆炖牛肉',
  emoji: '🥔',
  rating: 5,                // 1-5星
  notes: '今天的牛肉很嫩！',
  createdAt: 1746604800000, // 时间戳
}
```

## 关键交互

| 交互 | 行为 |
|------|------|
| 拍照按钮 | 点击弹出操作菜单（拍照/从相册选择） |
| 关联菜品 | 模糊搜索今日菜单 + 自定义菜品，以下拉列表展示 |
| 餐次自动识别 | 根据当前时间推算 meal 值，可手动切换 |
| 历史记录点击 | 弹出详情弹窗（大图 + 菜品 + 评分 + 备注） |
| 删除记录 | 长按卡片或左滑显示删除按钮 |

## 餐次自动识别规则

| 时间范围 | 餐次 |
|----------|------|
| 05:00 - 10:00 | breakfast |
| 10:30 - 14:00 | lunch |
| 17:00 - 21:00 | dinner |
| 其他时间 | 默认 breakfast |

## 统计指标

| 指标 | 计算方式 |
|------|----------|
| 本月做菜数 | `filter(r => r.date startsWith currentMonth).length` |
| 最爱菜品TOP3 | 统计 `menuItemName` 出现频率，取 TOP3 |
| 平均评分 | `sum(rating) / length` |

## 与其他页面的关联

- **今日菜单**：关联菜品来源（todayMenu + customFoods）
- **健康计划**：记录可作为饮食历史的一部分参考

## 技术实现

- 使用 `wx.chooseImage` 选择图片
- 图片存储在 `wx.env.USER_DATA_PATH` 目录下
- 本地存储使用 `storageAdapter.js` 的 `get/set` 方法
- 使用 `scroll-view` 实现月份切换和历史列表
